# Namespaces

Namespaces are a way of organizing your shaders, similarly to how you would do it in C#. A shader or module that's placed in a foreign namespace becomes inaccessible unless you import it to the shader or prefix an items name with it.

```sdsl
using MyGame.Utilities;

namespace MyGame.Player
{
    shader PlayerTeleportDiffusion : IMaterialSurfacePixel
    {
        override void Compute()
        {
            // Using the `GameUtilities` module from an imported namespace
            var diamondTexture = GameUtilities.GenerateDiamondTexture(4, 10);

            // Using the `Noise` module from the `ShaderGenerators.Common` namespace
            var noise = ShaderGenerators.Common.Noise.Quick();
            
            streams.matDiffuse = diamondTexture;
            streams.matColorBase = diamondTexture + noise * 0.04;
        }
    };
}
```

## Keyword cheatsheet

* `namespace` - declares a namespace for a block or entire file
* `using` - makes modules and shaders from a specific namespace accessible without prefixing them

## Declaring a namespace

Similarly to C#, you can declare a namespace for a block or the entire file.

```sdsl
namespace MyGame.Example
{
    // Things defined here are placed in MyGame.Examples
}

// Things defined here are placed in the global namespace
```

```sdsl
namespace MyGame.Example;

// Everything after the namespace declaration gets placed in MyGame.Examples
```

> [!TIP]
> We recommend that you follow the C# naming convention and place every shader under the namespace that starts with the name of your package (e.g. `NameOfGame`) and then follows the folder structure.
> 
> ```sdsl
> namespace NameOfGame.Materials.Enemy;
> 
> // This shader is in a file placed in NameOfGame.Game/Materials/Enemey/EnemyEyeEmissionTexture.sdsl
> shader EnemyEyeEmissionTexture : ComputeColor
> {
>     ...
> };
> ```

## Using code from other namespaces

By default, your shader has access to shaders and modules declared in the global namespace (meaning with no namespace) as well as those from parent namespaces. For example: `MyGame.Player.Example` can access shaders from `MyGame.Player`, `MyGame` and those that don't declare a namespace without having to mention them.

For other namespaces however, you will have to either prefix them with their namespace or use the `using` keyword.

```sdsl
using MyGame.Other;

namespace MyGame.Examples;

shader Example : ComputeColor
{
    override float4()
    {
        // A class from MyGame.Other is accessible because its namespace is declared at the top
        var val1 = OtherModule.GetValue();

        // Here's a class from another namespace that isn't declared at the top
        var val2 = MyGame.Utilities.UtilityModule.GetValue();

        return (val1 + val2) / 2;
    }
};
```

## Namespaces in C# and Game Studio

By putting a shader in a namespace you also change its full name in C# and Game Studio. For example: a shader named `MyShader` that's under the `NameOfGame.Common` namespace will now need to be referenced from Game Studio and C# using the `NameOfGame.Common.MyShader` name.

> [!TIP]
> To make sure you are using the correct name in C#, we recommend that you use the `NameOfShaderKeys.EffectName` property that's automatically generated by Stride.
> 
> ```csharp
> var effect = EffectSystem.LoadEffect(MyEffectKeys.EffectName).WaitForResult();
> ```
